# canary — 终端升级金丝雀发布协调库

进程内 Go 库：只负责产生升级/回滚指令并接收执行回执，不执行任何实际脚本。
状态全部保存在内存，单批次支持 5000 台终端、32 个调用方并发领取与回执。

## 能力

`Coordinator` 提供四个方法（均并发安全，效果等价于按调用先后的串行执行）：

| 方法 | 说明 |
| --- | --- |
| `CreateBatch(id, targets, pilots)` | 创建发布批次；目标集合与非空试点子集创建后不变 |
| `Next(batchID)` | 领取下一条指令；无可派发时立即返回 `ErrNoCommand`，不等待回执 |
| `Report(batchID, Receipt)` | 提交执行回执；重复回执幂等，不改变任何计数与终态 |
| `Status(batchID)` | 查看批次及各终端状态快照 |

## 使用示例

```go
c := canary.NewCoordinator()
err := c.CreateBatch("batch-1",
    []string{"dev-1", "dev-2", "dev-3"}, // 全部目标终端
    []string{"dev-1"},                   // 非空试点子集
)

// 执行器循环：领取指令 -> 执行脚本 -> 提交回执
for {
    cmd, err := c.Next("batch-1")
    if errors.Is(err, canary.ErrNoCommand) {
        break // 当前无可派发指令
    }
    ok := execute(cmd) // 由调用方执行实际脚本
    _ = c.Report("batch-1", canary.Receipt{CommandID: cmd.ID, Success: ok})
}

st, _ := c.Status("batch-1")
fmt.Println(st.State) // completed / rolled_back / ...
```

## 规则摘要

- 先试点：全部试点有最终结论且未触线才放大；试点终端不重复升级。
- 每台终端首次失败后最多再试 3 次（共 4 次尝试），4 次均失败才算最终失败；
  同一终端任一时刻最多一条在途指令。
- 失败比例严格超过 20% 立即回滚（试点期以试点数为分母，放大期以目标总数为
  分母）；恰好 20% 不触发；触线判断在每条回执处理时进行。
- 回滚：取消全部未派发升级/重试；所有升级成功终端（含回滚期间晚到的成功
  回执）各补偿一条回滚，立即可领取；全部在途升级回执到齐且所有回滚确认后
  进入 `rolled_back`。未触线且全部目标有最终结论进入 `completed`。终态不可回退。
- 指令 ID 稳定唯一（`<批次>/<终端>/<类型>#<序号>`）；回执可乱序、可重复，
  同一指令结果保证一致。

## 假设

升级失败不改变终端原版本；回滚执行一定成功；已领取指令最终都会收到回执。
不处理超时、失联与进程崩溃恢复。

## 测试

```sh
go test -race ./...
```

覆盖：试点 1/5 重试耗尽仍可放大、2/5 必须回滚；可重试失败不误触发；触线时
升级在途、晚到成功补偿回滚、不提前宣布终态、回滚集合恰等于成功集合；32 路
并发领取与回执、旧回执跨重试成功后重复到达的幂等性。
